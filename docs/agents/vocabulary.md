# 工程术语

本仓库的技能（`codebase-design`、`grilling`、`wayfinder`、`to-tickets`、`tdd`、`diagnosing-bugs`、`writing-for-agents`）正文是英文的，内部用一套自造的隐喻词。用中文回话时这些词会变成两种东西：生造的中文译名（「接缝」「前沿」「曳光弹」），或者干脆不翻译的英文单词（`seam`、`frontier`、`tracer bullet`）。两者都要用户自己猜。

这份文件是那些词的中文对照表。

## 什么词值得引进

判据两条，同时满足才引进：**中文名能自立**（不看解释也猜得到大意）**且比白话更短**。任一条不满足就别用那个词。

| 处理 | 词 | 写法 |
|---|---|---|
| 直接用中文名，首次给一次解释 | 深模块、纵向切片、阻塞边、红绿循环、迷雾、空指令、设计树 | 「红绿循环（red-green：先写失败的测试，再写最小实现让它过）」 |
| 用中文名，**每次出现都带一句白话** | 前沿、锚词 | 「前沿（现在就能问的那批决定）」 |
| **用白话，不引进术语** | 接缝、曳光弹、出雾 | 见下表 |

两个已经判过死刑的词：

- **接缝**（seam）读起来是实体接合处，而且和「接口」并排放着像同义词——读者分不出技能要区分的那层意思（接缝指位置，接口指位置上的约定）。**按功能说白话：测试语境说「测试打在哪个接口上」，替换语境说「可替换处」。**
- **曳光弹**（tracer bullet）是军事隐喻（曳光弹用来指示弹道往哪飞），不知道背景就等于零信息；而它指的就是「第一条纵向切片」，说白话比说术语还短。

**不要走「解释一遍然后用英文」这条路。** 它只在英文词本来就是你会说出口的词时成立；`seam`、`frontier` 不是，退到英文等于把难题丢回给读者。

## 用法

- 表里带中文名的，**首次出现给一句白话解释**并保留英文原名；标着「每次都带」的，每次都给。
- **同一个概念始终用同一个说法**；标着「用白话」的行不用术语。
- 下表的 `_Avoid_` 是禁用词；同义词列在那里就是为了不再漂移。
- 这份表为了可读性**有意偏离技能的原文用词**（技能要求 `seam` 非 `boundary`，我们这边说白话）。引用技能原文时照抄英文，正常行文按本表。

业务术语（任务、动作、动作链、水位、死信、北向/南向…）以 `CONTEXT.md` 为准，不在这里重复。

## 一词两义

三处需要显式区分，混用时要在句子里说清是哪个意思：

- **适配器**：在这里指 Adapter（代码结构）；在 `CONTEXT.md` 里是 `连接器（Connector）` 的禁用词。谈产品一律用「连接器」，谈代码结构才用「适配器」。
- **信息层级**：这里是文档写法的术语；界面设计里的「信息层级」是普通说法，不必按本表解释。
- **任务**：`CONTEXT.md` 的「任务（Job）」是本产品的可执行同步流程，和「一张工作票」不是一回事。拆票语境里一律说「票」。

## 不必收进来的词

下面这些看着像术语，其实中文里本来就常用，按平常说法写就行，不要因为本表而改变表达：**杠杆、局部、探路、认知负荷**。它们出现在这里只是提醒一句，不是要求。
