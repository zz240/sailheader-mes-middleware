# ADR-0005: 字段映射智能化方向

- 状态：已接受
- 日期：2026-08-16
- Amended by：映射引擎选型（2026-08-21，DS-10.2）——执行引擎定为 JSONata（结构化规则编译表达式，dashjoin）；JOLT/AtlasMap 出局；规则模型升级为递归组（多级表格编辑器），`mode:EXPRESSION` 提供手写表达式逃生通道。

## 背景

实施工程师配置字段映射是当前最耗时、最易错的环节（来源步骤、字段路径、转换类型全靠手填）。我们希望通过"更智能"的辅助降低配置成本。

## 决策

1. **智能化范围**：配置界面（A）+ 引擎（B）双侧。界面侧提供内联推荐与一键自动填充；引擎侧提供结构探测与配置期校验。
2. **实现策略**：先确定性启发式（结构探测、同名归一化、相似度、历史映射复用、样例值推断转换类型），可解释、可离线、无外部依赖。
3. **LLM 预留**：定义 `MappingSuggester` 接口，默认实现为规则引擎；LLM 实现（LangChain4j）作为可替换实现接入，具体接入范围另行决策。
4. **智能输入**：源 = 连库探测 + 样例 JSON 兜底；目标 = 样例/接口字段列表。
5. **验收标准**：新实施工程师 15 分钟内配通一条真实同步任务；字段映射 80% 由系统自动填充。

## 结果

为字段映射智能化建立 wayfinder 决策票地图，按决策票逐一解决（结构探测、匹配算法、LLM 接入、交互形态、评测基线）。
