# 失败采用"失败即停 + 重试退避 + 死信记录"

动作链中任一动作失败时，任务立即停止后续动作，按任务配置的重试次数和退避策略重试；最终失败的记录写入死信表供人工查看和重投。不承诺跨 HTTP/JDBC/MQ 的补偿式事务。

## Considered Options

- 失败即停 + 补偿事务：跨异构系统无法可靠补偿，复杂度高。
- 跳过失败继续：会产生部分成功、难以对账。
- 失败即停 + 重试 + 死信：语义清晰、可对账、可重投，是最终选择。

## Consequences

- 需要一张死信表，保存失败动作上下文、原始数据和错误信息。
- 每个任务有可配置的重试次数和退避策略。
