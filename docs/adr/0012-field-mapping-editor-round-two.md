## 背景

第一轮（ADR-0011，#99–#107）上线后，实施工程师在真机上提了六条。它们不是同一类东西：

1. **日期格式想手输自定义的。**
2. **拼接的片段里想用别的转换**（枚举转换、日期格式化……）。
3. **保存时还在校验已经清除的行。**
4. **校验是只报第一个错，还是所有行都报？**
5. **底部想要来源数据与映射后目标数据的对比演示。**
6. **来源字段想能导入 JSON 推出来**，不只是探测。

其中第 2、5 条**直接推翻第一轮写下的决定**，第 3、4 条落在同一段保存/校验链路上，第 6 条是第一轮写了方向
却没做的那半，第 1 条是小增量。

三条只读取证（前端行模型与保存链路、后端编译/校验链路、第一轮决策原文）把六条各自的**真实成本**问清楚了：

- 第 2 条的障碍在存储格式：`FieldMappingConfig` 与 `JsonataRuleCompiler.concatExpr` 两处把片段限死成
  「字符串常量或 `{"path": "..."}`」，而第一轮「不做嵌套」的理由正是**保住这个格式**。
- 第 3 条的真实成因不是「清掉的行被当成规则送去校验」（`configFromRows` 早就不收它们了），而是**请求里
  始终带着完整的目标字段清单**，后端据此报「必填的目标字段没有配置来源」，前端再把它定位回那一行。
- 第 4 条的前提是错的：「校验配置」这个接口**本来就是全量的**（结构 + 链 + 样例 + 编译，全部返回）；
  「只看到第一条」只发生在两处——行内只显示第一条、以及**保存时那道 400 只带 `problems.get(0)`**。
- 第 5 条不是「另一件事」：`JsonataFieldMapper.apply` 已经把「编译好的表达式跑在一份 context 上」做完了，
  而第一轮说的「受控边界」（引擎的 `setRuntimeBounds`）**本来就在引擎里，只是一直没接**。
- 第 6 条也不是从零建：后端已有 `StructureProbeService.probeSample`（一份 JSON 样例 → 字段清单），
  现在正用它把运行快照展开成来源清单。
- 顺带查明：`datePattern` 在结构、编译、草稿三层**都不校验**，非法格式串在运行时**必炸**
  （`JsonataFunctions.formatDate` 的 `ofPattern` 写在所有 try 之外）；而 `sourceFieldsStep` 为空会让
  三条样例检查**静默全部不判**。

## 决策

1. **拼接的片段可以再挂一层转换，深度锁死一层。** 片段形状变为「字符串常量」或
   `{"path": "...", "transform": "...", ...参数}`；允许的**片段转换**五种：直接取值、数字转换、
   日期格式化、枚举映射、行号。不给**拼接**（拼接是结合的，摊平即可）与**数组迭代**（会改变片段数量）。
   - 老的裸字符串片段与 `{"path": "..."}` 天然是「不带转换」的退化情形，读的时候原样兼容，**不做数据迁移**。
   - **每个片段各自选一个**：界面上那个下拉从现在的「常量 / 来源字段」两项变成六项（常量、直接取值、
     数字转换、日期格式化、枚举映射、行号），选中后参数就地展开——与行里那七种转换共用同一套参数编辑器。
     **一个片段只能挂一个转换，不能再往下套**——这就是「深度一层」。
   - **行号片段不带路径**：`{"transform": "INDEX", "startAt": 1}`（行号的源就是行号本身，没有可填的路径）。
     它只在**数组元素子行**里给，顶层拼接行上置灰并写明原因——与现在「行号转换在顶层置灰」同一条理由：
     `$index` 只在数组元素里有意义。
   - 这是存储格式**第一次**发生变化（ADR-0011 第 2 条的前提到此为止）。写出去的新片段旧版本读不懂，
     向下不兼容是单向的。
2. **日期格式化允许手输格式串**，四个预设保留；**同时把配置期校验补上 `datePattern` 合法性**
   （`docs/flows/transform-flow.md` F1 的建议 C）。理由：非法格式串在运行时必炸，而三层都不校验——
   只做输入框就是把一个必炸的口子装到界面上。有来源字段样例时按样例真解析一次，没有样例时只提示。
   （注意：这条校验的是**格式串合法**，不是「值和格式对得上」；后者要等试算。）
3. **清除的行就是「未配置的行」**（澄清 ADR-0011 决策 12）：不进草稿、不参与校验、不参与保存，
   「撤销」仍然只活在编辑器里。已清除的行**不会再拦住保存**。
4. **校验分两档，口径是「后端会不会拒」。**
   - **错误**（拦保存）：结构错（`FieldMappingConfig.problems()`）与链问题（`ChainConsistencyValidator`）——
     这两类是后端真的会拒的。
   - **警告**（只提示）：只在样例上成立的问题——必填没配、来源字段不在样例里、枚举没覆盖、文本写进数字。
     后端从来不拦这几种，编辑器也不该替它拦。
   - 这条**解决了第一轮规格里的自相矛盾**：`:148`（问题只提示，不阻止保存）与 `:54`（保存时被拦下并跳第一条）
     各对了一半——拦的是结构错，提示的是样例类。
   - **「必填的目标字段没有配置来源」降为警告，但仍然显示在那一行上。** 它说的是目标清单的事实
     （这个必填字段现在是空的），不是「这一行被校验了」。保存时那个「还有 N 行没配好……这些行不会被保存」
     的确认框因此不再和必填检查打架。
   - **保存那道 400 改成带全部结构问题**（`；` 连接，与链检查 `describeAll` 的口径一致），
     并且**把编译期错补进保存校验**（重复目标字段、前缀冲突）。现在这类错在任务停用状态下能保存进去、
     启用时才炸——门和事实不一致。
5. **来源字段样例有两个来源：结构探测与导入 JSON，并列，不是谁兜底谁。**
   - 导入收**对象或数组**；数组取**第一条**推字段，界面上注明「按第 1 条推的」。不合并所有元素——
     同名字段类型不一致时会推出一个根本不存在的联合类型。
   - **导入的样例归到顶部的「默认来源步骤」**（用户可改），界面写明「这份样例按『动作 N · X』的输出来算」。
     不能顺手设成空：`sourceFieldsStep` 为空会让「来源字段不在样例里」「枚举没覆盖」「文本写进数字」
     三条检查**静默全部不判**（`MappingSampleChecks` 的判据是 `step != null && step == sourceFieldsStep`）。
   - 目标字段清单的 JSON 导入**这一轮不做**（同一个「从 JSON 推结构」的能力，等它在来源侧跑顺了再复用）。
6. **底部加试算**（第三个页签，与编译产物那两个并列）：左边来源字段样例、右边这份草稿按样例算出来的
   目标报文，**点按钮才跑**，后端只读接口算，不写库。
   - **先整份跑一次**（与真实执行完全一致）；**抛错时再逐行跑一遍做归因**，界面上写明「整份没跑通，
     标红的是单独跑这一行的结果」。两段式是为了不撒谎：整份跑才是真话，逐行跑只是定位手段。
   - **手写 JSONata 也能试算**，并对 `mode:EXPRESSION` 强制启用 `setRuntimeBounds`（超时与递归深度），
     补上 `docs/research/mapping-framework.md:170` 那条记了却从没落地的备忘。
   - 这条**修订 ADR-0011 决策 9**（明确不做值的试算）：当时判给「另一件事」的理由是「需要在受控边界里
     真的执行表达式」，而那个边界在引擎里现成。
7. **术语一次补齐**（`CONTEXT.md`）：新增「片段转换」「来源字段样例」「试算」，补上第一轮就发现缺的
   「字段映射规则」「映射」「转换」。第一轮那条「这份文件不新增领域术语、`CONTEXT.md` 不改」的自我约束
   到此为止——六条里有三条（2、5、6）都需要术语表先站得住。
8. **顺手更正记录与用户可见文案**（实施时落地）：
   - `docs/flows/transform-flow.md` 的 **P8 写错了**：说 `$number("abc")` 静默变 undefined——引擎 0.9.10
     里是**抛 `NumberFormatException`**，任务直接失败。
   - **ENUM 查不到键不是「变成 null」，是这个字段从结果里整个消失**（对象构造只放非 null 的结果）。
     `MappingSampleChecks.java:238` 与 `frontend/src/mapping/transforms.ts:201` 的文案跟着改。
   - 第一轮规格第 210 行那句「先探测，探测不到就手动导入」说的是**目标**清单，不是来源清单——
     来源侧的明文依据只有 ADR-0005 决策 4 的「源 = 连库探测 + 样例 JSON 兜底」。

## 结果

- **存储格式第一次变化。** 读兼容老片段、写产出新片段；老配置不需要迁移，但新配置在旧版本上读不出
  片段转换。存储契约仍然只有 `rules`，表达式仍然不落库。
- **底部的两个页签变三个**（JSONata / 规则 JSON / 试算）。
- **校验从「一律拦」变成两档**，保存 400 从「只带第一条」变成带全部，编译期错的拦截点从「启用时」
  前移到「保存时」。ADR-0011 决策 12 的「清除」不再有拦保存的副作用。
- **两个能力第一次真的接上**：`setRuntimeBounds`（受控边界）与 `probeSample`（从 JSON 推字段清单）——
  都是既有备忘/既有实现，这一轮只是接线。
- **不做的事**：目标清单的 JSON 导入；嵌套数组的深层重排（仍走手写 JSONata）；`transform-flow.md` P9
  （中间层组的元素无法被更内层引用）的两条出路仍待评估；建议器接到界面上。
