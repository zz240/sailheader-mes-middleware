# 任务与动作链

一句话：一个任务就是一条按序号执行的**动作链**，可以手动跑、定时跑、也可以由外部触发；启用时把这条链编译成路由。

## 怎么建一条链

1. 任务 → 新建，选方向、配调度（不自动 / 间隔 / 每天 / 每周）和重试次数。
2. 加动作，按顺序编号。
3. 每个动作选种类、填自己的配置。
4. 点「校验」，链一致性和 SQL 一起查。
5. 启用——这时才编译成路由，改完配置要重新启用才生效。

## 八种动作

| 种类 | 做什么 |
|---|---|
| 读 SQL | 从库里读一批数据，按水位增量 |
| MQ 消费 | 订阅队列收消息（只能链首） |
| 字段映射 | 把上一步输出改成目标结构 |
| 写 upsert | 按业务键幂等写入 |
| HTTP 调用 | 出站请求，可配超时和成功条件 |
| MQ 发布 | 往队列发消息 |
| 一分多 | 一条拆成 N 条，或把响应还原回原来那几条 |
| 合并 | 攒住一批打成一个报文 |

## 链上有什么约束

| 约束 | 为什么 |
|---|---|
| MQ 消费只能链首 | 它是消息的入口 |
| 一个任务最多一个 MQ 消费、一个带水位的读 SQL | 两个入口会打架；两个水位没法对账 |
| 动作序号唯一 | 上下文按序号存 |
| 引用更早步骤时，那一步必须存在且序号更小 | 否则运行到那一步取不到值，只会静默出空 |
| 一分多的还原档要求上游有合并 | 它要靠成员清单回到原来那几条消息 |

约束在三个地方各拦一次：保存动作时、点「校验」时、启用前。三处用的是同一套判据。

## 数据结构

**任务**

| 字段 | 说明 |
|---|---|
| `direction` | `NORTH` / `SOUTH`，**只是业务标签**，不约束入口 |
| 调度 | 类型 + 间隔/时刻/星期 + 时区；内部编译成 cron，但不给用户看 |
| 重试 | `retryCount`、`backoffMs` |
| 最近运行 | 状态/时间/错误，由运行结束时统一回写，是投影不是权威 |

**动作**

`Action(index, type, addition)`。`addition` 按种类强类型化，每种一个配置类，各自校验。

## 实现要点

- **上下文**：每个动作的输出按序号存进 `edge.context`，字段映射的「来源步骤」就是这个序号（`0` = 任务输入）。HTTP 调用也写——写的是**响应**，同时把消息体还原成请求体。
- **三种入口**：MQ 消费 → 订阅端点；读 SQL → 定时轮询 + 直连；手动/重投 → 重放。
- **生命周期**：启用时注册路由、停用时移除；启动后重载已启用的任务；动作增改删后自动重建路由；重建失败自动停用并写 `lastError`。
- **任务串行**：同一个任务同一时刻最多一个运行，后来的触发直接跳过（返回冲突码），不排队。

## 改动落点：加一个动作种类，要动这八处

| # | 落点 | 改什么 | 漏了会怎样 |
|---|---|---|---|
| 1 | `model/ActionKind` | 加一项枚举 | — |
| 2 | `config/action/` | 加一个配置类，写 `validate()` | 坏配置能存进库 |
| 3 | `service/` | 加一个片段类：这类动作在路由里做什么 | 路由里没有这一步，动作被**静默忽略** |
| 4 | `RouteGenerator.appendChain` | 按种类接到新片段 | 同上 |
| 5 | `ChainConsistencyValidator` | 能不能链首、有没有来源步骤、和谁互斥 | 能配出跑不通的链，**启用时才炸** |
| 6 | `web/dto/ActionRequest`、`ActionView` | addition 的联合类型 | 前端发不上来 |
| 7 | `frontend/src/types.ts`、`JobsView.vue` | 种类联合 + 表单分支 | 界面上选不到 |
| 8 | 测试 | 片段单测 + 路由装配 + 端到端 | 回归漏网 |

加完先跑 `RouteGeneratorTest`——路由装配的回归都在这一个类里。

## 限制与绕法

| 注意 | 会看到什么 | 怎么办 |
|---|---|---|
| 改完配置不自动生效 | 已启用的任务还是旧路由 | 停用再启用一次 |
| 重建失败会停用任务 | 任务突然变停用，`lastError` 有原因 | 修好配置再启用 |
| 串行只在单进程内 | 多实例部署时互斥失效 | 需要改成数据库锁，另开票 |
| 方向不做校验 | 标了北向也能用 MQ 打头 | 这是有意的，方向只是标签 |

## 代码位置

| 区域 | 类 | 职责 |
|---|---|---|
| 路由装配 | `RouteGenerator` | 判定入口、按序号串片段、收尾 |
| 动作片段 | `ActionFragment`、`SplitFragment`、`AggregateFragment`、`RestoreFragment`、`ReadWriteFragments` | 每种动作在路由里做什么 |
| 簿记 | `StepLedger` | 消息步与运行记账 |
| 链校验 | `ChainConsistencyValidator` | 链约束 |
| 生命周期 | `RouteRegistry`、`RouteLifecycle`、`JobScheduler` | 注册/重建/调度 |
| 执行 | `JobExecutionService`、`JobRunGuard` | 跑一次、串行互斥 |

| 日期 | 事件 | 为什么 | 锚点 |

| 08-20 | 动作链通用化（动作种类 + 上下文 + 片段组合） | 固定南北模板无法插入"同步+通知"等组合 | DS-8 |
| 08-21 | 方向显式声明 | 入口推断会误判（MQ 消费也可以北向） | ADR-0002 |
| 08-24 | 动作变更自动重建路由 | 已运行的路由不感知配置变化 | — |
| 09-09 | 来源步骤的链一致性校验 | 删中间动作/重排后引用悬空，会让目标字段静默 null 且任务仍成功 | #89 |
| 09-20 | HTTP 响应进上下文，消息体还原为请求体 | 下游映射取不到响应字段；响应顶替消息体导致空响应时写库 NPE | ADR-0015 |

| 10-06 | 合并档 | 1000 条码就是 1000 次请求，对方批量接口被打爆 | ADR-0017 |
| 10-13 | HTTP 成功条件（路径 + 期望值） | 现场大量接口"永远 200、业务结果写在响应体里"，被拒的数据记成成功 | ADR-0015 |
