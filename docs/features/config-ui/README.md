# 配置界面与部署形态

Vue 3 + TS + Vite + Element Plus 独立前端工程；工程分离、部署合一。

## 当前设计（现状）

- **技术栈（ADR-0006）**：`frontend/` 独立工程（Vue 3 + TypeScript + Vite + Element Plus + vue-router）；页面：数据源 / 任务（含映射编辑器）/ 消息历史 / 模板 / 站点，路由在 `frontend/src/router/index.ts`。
- **API 客户端**：`frontend/src/api/client.ts` 统一走 `/api` 前缀、解包 `{code,message,data}` 信封，`code!=OK` 抛 `ApiError(code,message)`；`/mock` 代理到后端 mock 端点。
- **表单特化**：数据源/动作按类型渲染字段（六种 ActionKind 各自表单）；字段映射的配置整份在**全屏抽屉**里（`FieldMappingWorkbench.vue`），动作表上的「编辑映射」是它唯一的入口，动作弹窗里只留一句提示（#107 起旧的三栏 + 多级表格 + 推荐面板编辑器已删）。
- **开发期**：Vite dev server 5173 代理 `/api`、`/mock` → 8080，热更新；**部署期**：Docker 多阶段构建（node 构建 dist → 拷入 Spring Boot 镜像），单镜像、同源、无 CORS。
- **代码位置**：`frontend/src/views/*.vue`、`frontend/src/components/FieldMappingWorkbench.vue`、`frontend/vite.config.ts`、`spike/Dockerfile`。

## 视觉口径（ADR-0013）

界面外观以 `frontend/prototype/` 那几支高保真原型为准，**看视觉体系只认 `03-studio.html` 的 `:root`**
（十几个令牌 + 从它们推导的规则；四支原型合计 0 处手写 hex）。落地方式是**令牌层**：
一份 `frontend/src/styles/tokens.css` 既定义这套自有令牌、又覆盖 Element Plus 的 `--el-*`，
在 `main.ts` 里于 `element-plus/dist/index.css` 之后引入——**控件仍然全部是 Element Plus，不引新依赖**。

分三期，**先令牌后结构**：第 1 期令牌桥（2–3 个文件）→ 第 2 期编辑器这棵树换名（13 个文件，
158 处 hex / 53 处字号 / 14 处圆角）→ 第 3 期结构对齐（试算页签的结论条/计量条/证据表，见 #120）。
第 1 期只能买到「主色/圆角/边框/文字/底色/菜单色一次改完」，**买不到「像原型」**——真正的差距在
各组件里那些字面 px 与 hex。工作量实测与逐条依据见 `docs/research/ui-visual-refresh-scope.md`。

不在范围内：控制台五个页面的**信息密度重排**（消息历史 25 列、任务页 32 个表单项）——
dense utility 那套是给字段映射这类技术工具定的，表单型页面照搬未必合适，真要做需另开设计。

## 待办 / 已知限制

- 消息历史/模板/站点页面为表格 + 弹窗，交互相对简单。
- 动作弹窗里 FIELD_MAP 没有可编辑的配置：**新建**时点「保存」只能发一份空规则，后端会以「字段映射动作需要至少一条映射规则」拒掉（请走「去配字段映射」）；**已有**动作点「保存」会把编辑器里那份映射原样带上（按钮上写「改名称 / 序号顺便保存映射」）——它是改名称 / 序号唯一能存下去的办法。
- 第 1、2 期落地前，编辑器的 384 行自绘样式与五个业务页面的组件库默认外观**会有过渡期不一致**（ADR-0013「结果」一节写明了这是分期的代价）。

## 当前生效

- 工程分离、部署合一（ADR-0006）
- 表单按动作/数据源类型特化
- 数据源 addition 按类型特化（以 address 为准 + 高级 JSON 兜底）
- 字段映射只有一个入口：动作表上的「编辑映射」（全屏抽屉）；动作弹窗里字段映射只留提示（#107）
