# 配置界面与部署形态

一句话：前端是独立工程，和 Java 一起打成单个镜像、同源运行；外观以原型为准，用令牌层覆盖组件库。

## 有四个页面

| 页面 | 干什么 |
|---|---|
| 数据源 | 配外部连接（库 / MQ / HTTP），测连通、探结构 |
| 任务 | 建任务、编动作链、进字段映射 |
| 消息历史 | 看运行与消息步、断点重投 |
| 站点 | 站点信息、时区、外部触发用的 API Key |

## 表单是按类型长的

| 表单 | 按什么分 |
|---|---|
| 数据源 | 类型（MySQL / SQL Server / HTTP / RabbitMQ），每种一套字段 |
| 动作 | 八种动作种类，每种一套字段 |
| 字段映射 | **不在弹窗里**：整份配置在全屏抽屉，入口只有动作表上的「编辑映射」 |

## 开发和部署

| 环境 | 前端怎么跑 | 后端 |
|---|---|---|
| 开发 | Vite 5173，`/api` 与 `/mock` 代理到 8080，热更新 | 本地 8080 |
| 部署 | 构建出 `dist`，拷进 Spring Boot 镜像 | 同源 8080 |

单镜像、同源，所以没有 CORS 配置。

## 视觉口径

外观以 `frontend/prototype/` 那几支高保真原型为准。**看令牌只认 `03-studio.html` 的 `:root`**。

| 事 | 做法 |
|---|---|
| 落地方式 | 一份 `tokens.css` 既定义自有令牌、又覆盖 Element Plus 的 `--el-*`，在 `main.ts` 里排在 element-plus 样式之后 |
| 依赖 | 不引新的，控件仍然全部是 Element Plus |
| 分期 | 令牌桥 → 编辑器换名 → 结构对齐 |
| 第 1 期做不到什么 | 只能把主色、圆角、边框、文字、底色、菜单色一次改完，**买不到"像原型"**——真正的差距在各组件里的字面 px 和 hex |
| 不在范围 | 控制台页面的信息密度重排 |

## 实现要点

- API 客户端统一走 `/api` 前缀、解 `{code,message,data}` 信封，`code != OK` 抛 `ApiError`。
- 路由集中在 `router/index.ts`，新增页面只改这一处和侧边栏。

## 限制与绕法

| 注意 | 会看到什么 | 怎么办 |
|---|---|---|
| 动作弹窗里没有映射可编辑 | 新建字段映射动作直接点保存会被拒 | 走弹窗里的「去配字段映射」 |
| 改名、改序号只能连带保存映射 | 弹窗「保存」会把编辑器里那份一起带上 | 按钮上写明了这一点 |
| 分期没落地时外观不一致 | 编辑器是自绘样式，其它页是组件库默认外观 | 已知，第 2 期后消失 |

## 代码位置

| 区域 | 类 / 文件 | 职责 |
|---|---|---|
| 页面 | `frontend/src/views/*.vue` | 四个页面 |
| 字段映射编辑器 | `components/FieldMappingWorkbench.vue` | 全屏抽屉的装配层 |
| 路由 | `frontend/src/router/index.ts` | 页面路由 |
| API 客户端 | `frontend/src/api/client.ts` | 前缀、解信封、抛错 |
| 样式令牌 | `frontend/src/styles/tokens.css` | 自有令牌 + 覆盖 `--el-*` |
| 开发代理 | `frontend/vite.config.ts` | `/api`、`/mock` → 8080 |
| 打包 | `spike/Dockerfile` | 多阶段：node 构建 → 拷进镜像 |
