# 字段映射画布 — 设计说明

产物：`field-mapping-canvas.html`（单文件高保真原型，可直接打开）

演示场景取**真实数据**：来源 `spike/src/test/resources/json/erp测试数据.json`（ERP BOM 嵌套样例），目标与规则取 `docs/research/mapping-framework.md` §4.1–4.3（制品 → BOM / `mesBom`），规则形状对齐 `config/action/FieldMappingRule.java`，编译结果对齐 `mapping/JsonataRuleCompiler.java`。

---

## 1. 旧版界面（`MappingEditor.vue` + `MappingRowsTable.vue`）的问题

| # | 现象 | 根因 |
|---|---|---|
| 1 | 关系不可见 | 「来源→目标」是同一行里两个互不相关的下拉框，字段间关系只能靠读字段名脑补；谁映射到谁、哪些还没映射，都看不出来 |
| 2 | 来源字段下拉**永远是空的** | `fieldPaths` 只由 `loadSampleFields()` 赋值，而该函数在模板里从未被任何按钮调用（只被 `defineExpose` 暴露）。用户只能靠 `allow-create` 手打路径 |
| 3 | 样例 JSON 解析失败静默 | 裸 textarea + `JSON.parse` 外层 `catch { return null }`，树渲染为空且无任何提示 |
| 4 | 层级靠嵌套表格 | 数组组用可展开子表格 + 自引用递归组件，两层就同时出现 3 张表；「来源用相对路径」只有一行 12px 灰字提示 |
| 5 | 校验是事后的 | 点「校验配置」才知道缺什么，缺哪个字段要回表格里自己找，无行级定位 |
| 6 | 参数编辑脱离上下文 | ENUM / CONCAT 走二级弹窗，改完即关，看不到样例求值；`extra` 一列混装 CONSTANT/DATE/INDEX 三种语义 |
| 7 | 工具栏 4 个按钮平级 | 生成目标字段 / 获取推荐 / 一键自动填充 / 校验配置 都在左上，主次不分；且都要求先手工贴两份 JSON |

## 2. 设计方向

技术工具向（dense utility）：深浅两级中性色 + **单一信号绿**（`oklch(48% 0.15 150)`）；等宽字体承载字段路径、类型、样例值、编译表达式；状态色（警告/错误）只做信号。无英雄图、无渐变、无卡片阴影堆叠——产品本身就该是界面。

## 3. 新界面结构

```
app 条    edge-gateway 控制台 / 任务 · 动作 2 字段映射              ⌘S 保存 · 关闭
页头      字段映射   来源 db:erp_bom · 目标 mes.bom · 编译为 JSONata  [校验配置][保存映射]
动作链    ① READ_SQL ── ② FIELD_MAP（本动作）── ③ HTTP_CALL         映射结果写入 context[2]
画布      工具栏  只看未使用来源 · 自动匹配 · 实时预览        顶层已映射 6/6
          ┌ 来源结构 ─────── 连线区 ─────── 目标结构 ┐  ┌ 转换检查器 ┐
          │ erpBom.bomNo  ⋯──[拼接]──────── bomNo     │  │ 端点 / 转换 │
          │ erpBom.status ⋯──[枚举]──────── status    │  │ 参数        │
          │ erpBom.items  ⋯──[数组 7 元素]─ bomLines  │  │ 样例求值    │
          └ 诊断条：校验通过 · 顶层 6 条 + 组内 7 条 ──┘  │ 编译结果    │
          ┌ 映射结果（目标请求体） │ 编译后 JSONata ────┐  └────────────┘
```

**字段行**：等宽完整路径 + 类型徽标（`VARCHAR`/`DATETIME`/`ARRAY[14]`）+ 样例值 chip。已映射的行带极淡绿底、实心圆点（就是连线端点）；未映射的写「未使用」。来源行直接写出「已用于 2 处」，避免同一字段被悄悄复用。

**连线**：三次贝塞尔从来源端点连到目标端点，中点挂一枚转换标签（文本/整数/日期/枚举/常量/拼接/行号 1）。标签即入口：点它开检查器，悬停出现 ✕ 删除。选中时线加粗带柔光晕，其余线转灰虚线——**当前关系高亮、其余退后**。数组组规则画成一条粗线，标签显示「数组 7 元素」。

**拖拽建关系（本轮主改，见 §9）**：按住左侧字段向右拖，落到右侧目标字段松手即成关系——拖拽中画出橡皮筋，落到哪一行哪一行描边高亮，目标字段名与来源同名（或命中 `qty↔quantity` 一类别名）时提前标「推荐」。从已映射的目标字段往左拖回来源字段，则直接改接来源，不必先删再建。

**点选建映射（保留）**：点左侧字段 → 连线区底部浮出「已选来源 erpBom.moldNo」→ 点右侧目标即建成（默认「文本」）。键盘用户与触屏走这条路径——拖拽只在指针设备上启用，避免和列表滚动抢手势。

**数组作用域（本轮新增，对应 `iterate: FOR_EACH`）**：目标数组行（`bom.bomLines`）显示「来源 erpBom.items · 已映射 7/7 元素字段」和一个「进入作用域」按钮。进入后：画布只显示该数组的元素字段，作用域条写明「来源数组 erpBom.items · 每个元素 → 目标数组一行 · 来源用元素相对路径」，检查器把编译结果显示成 `$g0.materialCode`（组内的真实变量绑定），行号转换以 `$i0 + 1` 呈现并禁用 INDEX 之外的歧义（`INDEX 只能在组内`）。返回顶层用 Esc 或「返回顶层」。**层级不再靠缩进表格，而是靠可进出的作用域。**

**转换检查器**（右栏，替换原 ENUM/CONCAT 弹窗）：端点、转换类型 chips、类型化参数（日期 pattern 下拉 + 自定义输入、枚举键值表可「从样例补一个」并列出样例中出现的值、常量、拼接片段）、**样例求值**（把第 1 行样例值跑一遍转换后并排显示结果，`undefined` 会明确标注为「JSONata 静默缺失」）、**编译结果**。

**诊断条（常驻）**：校验从「事后按钮」变成常驻状态。点击可逐条跳到出问题的规则或字段；错误/提示/说明三级：必填未映射、ENUM 缺表、CONCAT 缺片段、INDEX 用于组外、`datePattern` 非法（含建议器会产出的非法 `ISO-8601`）为错误；可选未映射、同源复用为提示；数组组映射进度为说明。

**映射结果与编译产物（底部抽屉）**：左栏是按目标路径还原嵌套结构的请求体（未映射字段不出现），右栏是整棵规则树编译出的 JSONata（组节点展开为 `[ $map(...) ]`）。回答「这样配到底发出去了什么」。

## 4. 与真实契约的对齐

- 规则字段与 `FieldMappingRule` 一致：`sourceStep / source / target / transform / constant / enumMap / datePattern / iterate / children / parts / startAt`；来源路径写成完整路径（`erpBom.productCode`），组内为相对路径。
- 转换类型 = `TransformType` 全量七种；编译展示用真实形状：`$dateFormat(...)`、`$lookup({...}, ...)`、`$number(...)`、`&` 拼接、`$i0 + startAt`、组输出 `[ $map(...) ]`。
- 校验文案对齐后端写时校验（`FieldMappingConfig.validate`）：组节点缺 `iterate`、组内子规则不得再选 `sourceStep`、`INDEX` 只能在数组组内且 source 必须为 `$index`、`CONCAT` 需要 parts、常量需要 constant、枚举需要 enumMap。
- 页头把动作链与 `sourceStep` 显式画出来，针对的是「来源步骤选错 → 目标字段静默为 null」这一已知缺陷。
- 「确认为人工确认」对应建议器历史回流（`origin = exact/infer/auto` → manual），即 ADR-0005 的资产沉淀口径。

## 5. 与旧版的取舍

- **保留**：左来源 / 中关系 / 右目标的心智；ENUM 与 CONCAT 的可视化编辑（不写 JSON）；样例求值；递归规则树的存取；建议器入口。
- **替换**：中间从「表格 + 下拉框」换成「关系画布 + 转换标签」；操作对象从「一行」变成「一条关系」。
- **下沉**：校验变成常驻诊断条；参数从弹窗变成侧栏检查器；「获取推荐 + 一键自动填充」合并为「自动匹配」，命中来源在检查器可追溯。
- **新增**：数组作用域；样例值直接显示在字段行上（来源下拉恒空的根因是「样例没接进 UI」，所以让样例本身成为可见事实）。

## 6. 迁移到前端代码

新增 `MappingCanvas.vue`（画布 + 连线 + 待选态 + 作用域）、`MappingInspector.vue`、`MappingDiagnostics.vue`；`mapping/rows.ts` 的 `MapRow` 与 `getConfig/setConfig` 递归存取可原样保留——画布与旧表格可以共用同一份 `rows`，用工具栏的「画布 / 表格」切换灰度并行，确认无回归后再删 `MappingRowsTable.vue`。连线层需要在 `ResizeObserver` + 容器滚动时重算（原型里已按这个结构实现）。

## 7. 尚未覆盖

- 三层以上的嵌套组（本原型做到「顶层 + 一层数组作用域」，可再进一层用同样的作用域机制）；`$root` 跨层引用目前只在检查器文案中提示，未提供点选入口。
- 多行样例（当前只对第 1 行元素求值）、映射模板套用、批量选择（框选多个字段一次落多条关系）。
- 拖拽时列表不自动滚动，长列表要先把目标滚进视野；跨作用域拖拽（从顶层字段直接拖进数组作用域）未开放。
- 同源多目标时的冲突提示目前只是「说明」级，未做强制确认。

## 8. 数据来源

- 来源样例：`spike/src/test/resources/json/erp测试数据.json`（`erpBom` + `items[]` 两条真实中文制造业数据）。
- 目标与规则：`docs/research/mapping-framework.md` §4.1–4.3；断言用例 `spike/src/test/java/.../mapping/JsonataRuleCompilerTest.java`。
- 契约与语义：`docs/features/field-mapping/README.md`、`spike/src/main/java/com/example/edgegateway/{config,mapping}/`。
- 除上述真实字段与取值的界面文案外，原型不含任何编造指标。

## 9. 本轮迭代（拖拽建关系 + 缺陷修复）

对照真实的旧界面（`frontend/src/components/MappingEditor.vue`、`MappingRowsTable.vue`）复核后，本轮把"建立关系"这一个动作做成画布该有的样子，并修掉三处会被用户当场撞见的缺陷。

**新增：拖拽建关系**

| 行为 | 细节 |
|---|---|
| 来源 → 目标 | 按住左侧字段拖动（阈值 5px 才算拖拽，否则仍按点选处理）；落点行 2px 描边 + 端点放大，无效落点橡皮筋转红并标注原因 |
| 目标 → 来源 | 从已映射的目标字段往左拖，落回来源字段即改接来源，规则 id、转换参数、组内子规则全部保留，不重建 |
| 数组 | 来源 `ARRAY` 行只能落到数组目标，落下即建 `iterate=FOR_EACH` 组并进入作用域；叶子字段落到数组目标、或数组落到叶子字段，都会被拦下并说明原因 |
| 预测 | 同名字段与 `qty↔quantity / no↔number / amt↔amount / vendor↔supplier` 别名命中时，目标行提前标「推荐」——判据与「自动匹配」共用一份 |
| 同一目标一条规则 | 落到已映射的目标字段即替换原来源，并在提示里写明被替换的是谁（对齐后端 `config.rules` 语义） |
| 兜底 | Esc 取消、松手在空白处给出「拖到哪一侧」的提示、触屏与 ≤1120px 只保留点选 |

**修复**

1. **检查器输入框失焦**：原来每次 `input` 都 `renderInspector()` 整块重建，参数框敲第一个字符就失去焦点。改为给「样例求值 / 编译结果 / 该规则的问题」三块加 id 就地更新（`softRefresh`），键盘输入与实时求值不再互斥。
2. **来源数组行永远显示未映射**：组规则的 `target` 是 `bom.bomLines`，而代码用 `ruleForTarget('erpBom.items')` 反查，永远查不到。改用 `ruleForSource` 反查，现在会写出「已映射到 bom.bomLines · 7/14 元素字段」。
3. **落点判定在重绘之后**：`pointerup` 里先 `endDrag()` 重绘、再判断落点所属列表，节点已脱离文档使 `contains()` 恒为 false。改为先算落点再重绘。

**同时清理**：页头场景统一为 `db:erp_bom → mes.bom`（原文案残留 `po_order/mes.purchase-order`，与画布里的 BOM 数据自相矛盾）；目标字段计数由「4 顶层字段」更正为 5；删除死代码 `previewLines`、重复的 `norm`、未使用的 `state.filterUnmapped`；字段路径 12.5→13px、次要信息 10.5→11px、行高 44→46px，拖拽态、可落点、推荐态、悬停态的对比度逐一定义并保持文字不低于默认态。

## 10. 本轮迭代：关系本身成为可编辑内容（`field-mapping-workbench.html`）

反馈是「配置映射非常粗糙，想用更现代的方式建立字段与字段之间的关系」。复核后判断：粗糙不在配色或间距，而在**关系这件事本身没有被表达出来**——旧画布用「左列一坨、右列一坨、中间一片空档拉几条贝塞尔线」来代表关系，线是唯一的载体，而线恰恰是最难读、最难改、最难维护的载体。于是本轮换掉的是关系的**表征模型**，不是皮肤。

**保留**：已锁定的令牌与字体（深浅两级中性 + 单一信号色，等宽承载路径与样例值）、真实数据与真实契约（`FieldMappingRule` / `JsonataRuleCompiler` 的编译形状与校验项）、编译预览抽屉、常驻诊断条。**未换肤。**

### 10.1 旧表征 vs 新表征

| # | 旧画布的表征 | 问题 | 新工作台的表征 |
|---|---|---|---|
| 1 | 关系 = 一条横跨空档的贝塞尔线 | 要一直重算、一直渲染、滚动即错位；线和字段对不上号就得顺着找 | 关系 = **目标行内的一段表达式**：`[productCode]` 或 `"BOM-"` ＆ `[productCode]`。关系即内容，不需要任何解码 |
| 2 | 转换类型 = 标签「拼接」 | 只说了类型，没说拼的是什么 | 标签变成**结构**：片段可增删、可换字段、可在字段与字面量之间切换。`CONCAT` 不用进二级弹窗 |
| 3 | 来源端只是采样值的展示 | 看不到「这个来源配给谁」 | 来源行写出 `已用于 N 处`，悬停目标行时它引用的来源行同时高亮 |
| 4 | 连线一直在 | 视觉噪声，且掩盖了真正的信息 | 连线**只在悬停 / 选中时实体化**：常态是极淡虚线，激活时变实心并带一个流动光点，其余转灰退后 |
| 5 | 拖拽手柄是 7px 的圆点 | 命中区太小，指针体验差 | **整行即手柄**；落下时目标行内出现插入位并描边 |
| 6 | 无法看到类型是否对得上 | `quantity: INT → qty: INT` 与 `INT → VARCHAR` 看起来一样 | 行尾给出 `INT → VARCHAR` 适配提示与一键「转为文本」 |
| 7 | 数组只能进一层 | 老界面的 `MappingRowsTable` 其实是递归的，原型表达不了 | 作用域支持**递归**：面包屑可回到任意一层，来源侧提供 `$root.` 跨层引用（对齐编译器 `sourceExpr` 的 `$root` 前缀） |
| 8 | 校验只覆盖单条规则的参数 | 漏掉后端编译期会直接抛错的两条 | 补上 **目标字段重复映射** 与 **目标字段前缀冲突**（`JsonataRuleCompiler.insert` 的约束），并支持从诊断跳进对应作用域的那一行 |
| 9 | 「＋添加」按钮常驻 | 每行两个按钮，未映射行很吵 | 只在未映射行给「＋选择来源字段」，已映射行的「＋」缩成表达式尾部的小图标 |

### 10.2 建立关系的三条路径

1. **点**：点左侧字段 → 点目标行的「＋」→ 弹出可搜索字段选择器（带类型徽标、样例值、已引用次数、`$root` 分组）→ 回车即成关系。
2. **拖**：整行按住往右拖，橡皮筋实时反馈合法性（数组只能落数组、叶子只能落叶子），落点行描边高亮；从已映射的目标行往左拖回来源字段则**改接**来源，规则 id 与参数全部保留。
3. **自动匹配**：同名 → 同义（`qty↔quantity`）→ 日期/状态模式推断，命中后行尾标「同名 / 推断」，可一键「确认为人工」写入历史（对应 ADR-0005 的资产沉淀口径）。

### 10.3 与契约对齐的编译视图

底部抽屉左栏是按目标路径还原的请求体（未映射字段不出现），右栏是规则树编译出的 JSONata：

```
{
  "bomNo": "BOM-" & $s_1.productCode,
  "bomLines": [ $map($s_1.items, function($g0, $i0) { {
    "lineNo": $i0 + 1,
    "qty": $number($g0.quantity),
    "unit": $lookup({"PCS":"件","SET":"套"}, $g0.unit)
  } }) ]
}
```

组内子规则的 `source` 仍是元素相对路径（与 `children` 语义一致），界面上按作用域还原成完整路径去连左侧的行——这层转换集中在 `srcFull()` 一处。

### 10.4 尚未覆盖

- 三层以上的嵌套数组（机制已递归，样例数据只到两层）：`erpProcessRoute.operations` 这类真实数组可直接进第二层作用域，第三层未造数验证。
- 跨作用域拖拽（从顶层字段直接拖进数组作用域）未开放，需要先进入作用域再拖。
- 拖拽时列表不自动滚动；批量选择（框选多个字段一次落多条关系）未做。
- 未映射的**可选**字段只给提示级 diagnostic，未做「确认留空」的显式状态。

## 11. 本轮迭代：关系写成一个句子，句子当场求值（`field-mapping-studio.html`）

复核真实前端后确认「粗糙」的第一现场不在画布，而在产品本身：`MappingEditor.vue` 把 `loadSampleFields()` 挂在 `defineExpose` 上（L507），**全仓没有任何调用点**（`grep loadSampleFields` 只命中定义与 expose），于是 `fieldPaths` 恒为空数组，来源字段下拉永远是空的——用户只能靠 `allow-create` 手打路径。旧表征（一行两个下拉框 + ENUM/CONCAT 二级弹窗）又让「关系」只能靠读字段名脑补。

第 10 节的 workbench 把关系搬进了行内表达式，方向对，但证明链是断的：编译预览的数组按目标名 `bomLines` 取数（取不到）、INDEX 编出未绑定的 `$i1`、检查器与抽屉各用一套求值器且互相矛盾。**因此本轮换的不是表征，而是把「证明」做成一等公民。**

### 11.1 一个模型：关系 = 一段可编辑表达式，值当场算给你看

```
目标字段              关系表达式（可编辑）                     样例求值
bom.bomNo       *     "BOM-" & [erpBom.productCode]      →  BOM-PRD-BUMPER-001 ✓
bom.productName *     ＋ 拖入来源字段                     →  未建立关系
▾ bom.bomLines  *     $map([erpBom.items], 每个元素 → 一行)  →  2 行  ✓
    lineNo      *     ＋ 拖入来源字段                     →  未建立关系
    qty               $number([quantity])                 →  1, 24  2 元素 ✓
    unit              $lookup({PCS→件, SET→套}, [unit])   →  件, 件  ✓
```

关键差别：**转换类型这个字段没有了**。旧界面要「先选转换类型、再去弹窗配参数」，因为转换是规则的属性；这里转换是表达式里的算子，`$number(...)`、`$lookup({...}, ...)`、`"BOM-" & ...` 就是编译出来的 JSONata 本身。改算子 = 改表达式，参数就在算子旁边原地编辑（枚举表、日期模式、常量都是行内展开，不再有弹窗，也不再有第三个界面——检查器被删掉了，行就是编辑器）。

### 11.2 与旧表征的逐条对照

| # | workbench 的问题 | 本轮做法 |
|---|---|---|
| 1 | 三套求值器，检查器 / 左栏 / 右栏互相矛盾 | 只有 `evalNode` 一棵求值树，行内样例值、请求体、诊断、编译四处全部由它驱动 |
| 2 | 请求体的数组永远渲染成中文占位符（按目标名取数取错） | 组行按 `srcPath` 取源数组，逐元素求值，真实输出 2 行 |
| 3 | INDEX 编出未绑定的 `$i1` | `$i` 下标由规则深度推出（顶层组 = `$i0`），与 `indexExpr` 一致，本文件已断言 `"lineNo": $i0 + 1` |
| 4 | 「第 1 行样例」是写死的、只算一行 | 组内字段对**每个元素**求值并排显示（`1, 24`），行号显示 `1, 2` 而不是编一个 `'1 … 2'` 字符串 |
| 5 | 转换类型只是 10px 灰尾注，无法扫读 | 算子本身就是表达式里的实心块，读一行就知道这条关系做了什么 |
| 6 | 删除是 hover-only、不可聚焦、不可撤销 | 表达式块与删除按钮都可 Tab 聚焦、可回车触发；清除关系给带「撤销」的 toast |
| 7 | 集合级动作（谁引用了 X / 哪些是 ENUM）只能靠悬停反查 | ⌘K 命令面板：自动匹配、校验、保存、展开/收起、跳转到任一目标字段 |
| 8 | 无效落点只说「红」，原因在松手后的 toast | 拖拽时按「数组↔数组、叶子↔叶子、作用域内↔作用域内」判定，无效即红框 + 松手时给出**具体到该拖哪个字段**的原因 |
| 9 | 数组层级要「进入/退出作用域」，退出后上下文消失 | 数组组就是账本里可折叠的父行，子行缩进常驻；跨层引用写成 `$root.` 前缀，编译为 `$s_1.x` |

### 11.3 建立关系的三条路径（都可键盘完成）

1. **点**：点货架字段 → 点目标行的空槽 / 字段块 → 行内展开可搜索选择器（↑↓ + 回车，带类型徽标、样例值、已引用次数），回车即成关系。选中某行后，在货架上按回车可直接接上。
2. **拖**：货架整行可拖；落到**行**＝替换该行来源（是拼接就追加片段），落到**表达式里的某个字段块**＝只换那一块，算子和参数保留。数组字段只能落到数组组行，元素内相对字段只能落到组内——落错会说明原因。
3. **自动匹配**：同名 → 别名（`qty↔quantity`）→ 数组组内 `lineNo` 一类按行号推断。命中后行内标「同名 / 推断」，改一下即转「人工」（ADR-0005 的资产口径）。起始态刻意留 3 条空关系（6/9），一次自动匹配到 9/9。

### 11.4 验证方式（不靠肉眼）

把页面里的 `<script>` 抽出来，在 Node 里用最小 DOM 桩跑真实逻辑，对着真实样例断言：

- 初始态：覆盖率 6/9；诊断 2 错 4 说明（必填未映射 / 组内进度 / 来源复用 2 处）
- 自动匹配后：9/9、**0 错误**；请求体 `bom.bomLines` 是 **2 个真实对象**，`lineNo` 为 1、2，`qty` 为数字 1、24，`unit` 为「件」
- 编译结果逐字包含 `"BOM-" & $s_1.erpBom.productCode`、`[ $map($s_1.erpBom.items, function($g0, $i0) { {`、`"lineNo": $i0 + 1`、`$number($g0.quantity)`、`$lookup({"PCS":"件","SET":"套"}, $g0.unit)`
- 规则 JSON 可 `JSON.parse`，`iterate=FOR_EACH` / `children` / `parts` 形状对齐 `FieldMappingConfig.toMap()`
- 反向断言：顶层拖入元素内相对字段被拦下；顶层用行号算子会被诊断判错；组内引用外层自动写 `$root.` 且编译出 `$s_1.` 前缀
- 五类行内面板（字段选择 / 算子 / 常量 / 枚举 / 日期）、两种过滤、折叠态各渲染一遍无异常

### 11.5 尚未覆盖

- **单一样例、不可替换**：仍然只跑 READ_SQL 的那一份真实样例，没有「贴自己的样例」入口（旧界面的能力），多行样例只到 `items` 的 2 个元素。
- **来源只能从探测到的字段里选**，没有手打路径出口——拼错路径从构造上不可能发生，代价是样例里没有的字段暂时映射不了。
- 三段以上的嵌套数组未造数（机制随 `children` 递归，`erpProcessRoute.operations` 真实存在但未接成第二个组）。
- 批量框选多个字段一次落多条关系、拖拽时列表自动滚动、未映射可选字段的「确认留空」显式状态，均未做。
- 目标字段清单来自 §4.1 的 BOM 契约（4 顶层 + 5 组内），不支持自定义目标字段。


## 12. 本轮迭代：试算结果按「一次执行的判决」来展示（`field-mapping-studio.html`）

### 12.1 旧展示的三处失真

1. **值是截断的**：账本右列把结果 `short(…, 24)` 之后只剩一行省略号，全值藏在 `title` 里；数组组只有一句「2 行」，看不出第 2 个元素到底算出了什么。
2. **少掉的东西看不见**：`requestBody()` 把求值为 `undefined` / 报错的行**直接跳过**。于是「这个字段静默消失了」——试算最该说的一件事——在界面上完全没有位置。
3. **说不出两段式**：`MappingTrialResult` 的 `ran=true/false` 是两种不同性质的事实（整份跑通＝真实执行那一次；`failures[]` 只是单独跑某一行做定位），旧的抽屉只有一块 JSON，没有地方承载这层区别。

### 12.2 论点

试算不是「配置长什么样」的预览，而是**一次带判决的执行**。所以展示顺序照执行报告来，而不是照 JSON 查看器来：

1. **先给结论**：整份跑通 / 整份没跑通 / 编译不过，三句话，引擎原话照抄不转述。
2. **证据逐行对齐**：`输出路径 ↔ 试算值 ↔ 产出它的规则` 三列；**没值的字段也占一行**并写明原因（未映射 / JSONata 静默省略 / 空值）——「少了一个字段」必须可见。
3. **能定位**：报表里任意一行点一下跳到账本里那条关系；归因块里点「定位到这一行」同样跳过去。

### 12.3 界面结构（抽屉第一页签，默认展开）

- **结论条**：绿点「整份跑通 · 这就是真实执行会发出的目标报文」／红点「整份没跑通 · <引擎原话>」／红点「编译不过 · <校验项>」，右上角注明样例口径。
- **计量条**：`落值字段 5 / 8`、`目标数组 2 行`、`未映射 3`、`静默省略 0`，每格带 `title` 说明口径。算术是闭合的：落值 + 未映射 + 省略 = 目标叶子字段总数。
- **证据表**：顶层每个目标字段一行；数组组行显示 `N 行` 并声明「几个来源元素落了行」，其下每个元素字段一行，**把各元素的取值横向摆开**（`[1] "MAT-718H"  [2] "MAT-SKD61"`），一眼回答「是不是每个元素都算出了东西」。
- **归因块**（仅整份抛错时）：抬头写明「标红的是**单独跑这一行**的结果——它是定位手段，不是真实执行会这样（ADR-0012 决策 6）」；定位不到具体某一行时，明说「定位不到就不硬指一行」。
- **原始 JSON 视图**：结构化 / 原始 JSON 一键切换，工程师要看的那份没丢。

### 12.4 对齐的真实契约

- `POST /api/field-mapping-editor/trial`（`MappingTrialRequest{draft, sampleJson, sampleStep}` → `MappingTrialResult{ran, output, error, failures[]}`），**只读、不落库**，点按钮才跑——所以是「运行试算 ⌘⏎」而不是随改随跑。
- `MappingTrialService.attribute()` 的递归口径照搬：只从顶层行往下走；组行**单独跑跑通了就跳过它**（错的不是它）；组行不成时只报「单独放回这个组里跑也不成」的子行；都定位不到就不报。
- **编译不过**走 `failed(message)` 那一支：没有 `output`、没有 `failures`，界面上写「编译不过就谈不上逐行」。
- 校验与试算刻意分开：校验是静态查（便宜、保存前必跑），试算是真执行（要资源上限、点按钮才跑）。两者在界面上各占一处，措辞上也点明「两件事分开看」。

### 12.5 与账本的双向联动

- 账本右列的「样例求值」改名**试算值**，整格变成按钮：点它开抽屉、切到试算页签，并在证据表里高亮 `data-ttarget` 对应的那一行。
- 报表里的行反向跳回账本：组被折叠就展开、过滤在「只看未映射」就切回全部，再滚动到该行——**定位永远有效**。
- **过期即冻结**：跑完把当时的规则指纹（`draftKey = rulesJson()`）一起存进结果，渲染时比对。草稿一变就挂「草稿已改动 · 下面还是上一次试算的结果」横幅并给「重新试算」；**报告里的规则文字与字段路径是跑的那一刻的快照**，不会跟着账本一起变（否则会出现「新规则 + 旧取值」这种更糟的错配）。

### 12.6 验证方式（不靠肉眼）

同样把 `<script>` 抽出来用最小 DOM 桩跑真实逻辑，六种状态各渲染一遍落盘核对：

- 初始态：`落值 5/8 · 未映射 3 · 静默省略 0 · 目标数组 2 行`，输出 `bom.bomNo="BOM-PRD-BUMPER-001"`、`bomLines[1].qty=24`、`unit="件"`
- 补齐三行后：`落值 8/8 · 未映射 0`，`lineNo` 逐元素为 1、2
- **静默省略**：把来源改成样例里不存在的路径 → `落值 7/8 · 静默省略 1`，该行在表里标红
- **整份抛错 + 逐行归因**：组内某行套错日期转换 → `ran=false`，归因**恰好一条**（`row=3.3, target=qty, parent=bom.bomLines`），不再是「组行一条 + 子行一条」的重复，也不会把组行的 `target` 写成子行名
- **编译不过**：常量留空 → 只走 `failed()` 那一支，`failures=[]`，界面写「逐行归因未进行」
- **过期冻结**：跑通后改草稿再渲染 → 横幅出现，且报告里仍写**旧来源** `erpBom.productName`、不出现新来源 `erpBom.customerName`

### 12.7 尚未覆盖

- **样例仍不可替换**（与 §11.5 同一条）：试算面板上写了样例来源，但没有「粘贴 JSON / 从运行记录探测」的入口，也没有「还没有可试算的来源样例」那条空态的实物。
- **归因只到「哪一行」**：引擎原话照抄，不做「可能是枚举表没覆盖」这类转述——真要提示，得有人先定义错误分类。
- **手写表达式模式（`mode=EXPRESSION`）**：那一边没有「行」可归因，界面文案留了位，但草稿里还没有模式开关可切。
- **不落库的试算历史**：只保留最近一次，没有「和上一次比」的对照；报表也没有导出。
- 数组元素超过 3 个时横向对照只摆前 3 个 + `+N`，没有逐元素展开。
