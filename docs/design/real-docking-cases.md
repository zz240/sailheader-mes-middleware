# 真实对接场景目录（供挑选）

> 用途：从工业现场常见的 **MES 对接** 与 **工业互联网对接** 形态里挑出要模拟的场景。
> 每条给：业务流 / 方向 / 触发与频率 / 数据形态 / **本机替身怎么做** / 检验本产品哪一条 / 已知差距。
> 挑完（在本文档上标记）我再把选中的写成可跑的场景与配置，逐个做对。
> **本批已选中并落成规格：** A2 / A3 / A4 / A5 / A7 / B1 / B6 —— 见 [docking-scenarios-spec.md](docking-scenarios-spec.md)（场景靶子 + 替身拓扑 + 数据模型 + 失败面）。
> 术语以 `GLOSSARY.md` 为准；本产品当前能力边界见 §E，判断依据都带文件与行号。

## 0. 挑选建议（第一批先做这 6 条）

| 编号 | 一句话 | 为什么先做 |
|---|---|---|
| A2 | 云上 MES 下发物料主数据/BOM 到客户库 | 南向主数据同步，最能代表「MES → 客户」日常；幂等 upsert + 全量/增量口径 |
| A3 | 云上 MES 下发生产工单/派工到车间前置库 | 南向单据，含单据头 + 工序行（数组层级映射） |
| A4 | 车间报工/进度回传 MES | 北向高频小报文，直接压 **幂等、乱序、重复上报、断点重投** |
| A5 | 客户 ERP 采购/收料回传 MES | 北向单据，且客户 ERP 常是 **SQL Server** → 逼出方言差距（§E.2） |
| B1 | 设备数据采集上云（边缘 → 云 IoT 平台物模型属性上报） | 工业互联网最核心的一条；暴露「无 MQTT/物模型」这一层差距 |
| B6 | 一物一码 / 标识解析（模具、零件、刀具赋码追溯） | 工业互联网另一典型；用 HTTP 就能真接，含签名与批量核对 |

## D. 工业互联网的硬骨头（非功能与可靠性）

| 编号 | 场景 | 现场为什么常见 | 本产品今天的状态 |
|---|---|---|---|
| D1 | 断网续传（边缘缓存 + 恢复补传） | 厂区网络抖动、云侧维护 | 失败即停 + 水位不推进 → 重跑补读（可模拟验证） |
| D2 | 时钟偏移与乱序（设备时钟不准） | 设备侧 NTP 缺失 | TIMESTAMP 水位含边界重读；需验边界行为（`ReadSqlBatcher:71-84`） |
| D3 | 重复上报 / 重发幂等 | 设备与网络都会重发 | 南向按幂等键 upsert；北向靠目标端业务键去重（可模拟验证） |
| D4 | 大 payload / 背压 / 分页 | CMM 点位、整批主数据 | `batchSize` 分批 + 整批成功才推水位（可模拟） |
| D5 | 签名与鉴权（AK/SK + HMAC、双向 TLS） | 云平台几乎都要求 | 今天只有 Bearer token 与站点 API Key（`HttpDataSourceConfig:12`、`ApiKeyService`）；HMAC/双向 TLS 需新能力 |
| D6 | 数据质量（空值、越界、单位换算、编码） | 现场数据脏 | 映射层可做（ENUM/CONSTANT/CONCAT/DATE/INT），越界与拒绝策略未定义 |
| D7 | 日终对账（条数/金额） | 上线后运维第一诉求 | 有消息历史（`/api/history/*`）可查，但没有「对账」这个动作/报表 |
| D8 | 新旧系统并行与灰度回滚 | 切换期必需 | 可并行跑两条链（可模拟） |

## E. 本产品今天的对接能力边界（事实，带证据）

1. **连接器只有三种**：`HTTP`、`MYSQL`、`RABBITMQ`（`model/DataSourceType.java:4-8`；`DataSourceManager:99-116` 强转 `MysqlDataSourceConfig`）。Kafka / MQTT / OPC UA / SOAP / SFTP 都要新增能力。
2. **SQL Server 不是加个驱动就行**：`ReadSqlBatcher:83` 拼 `LIMIT`、`StructureProbeService:116` 用 `SELECT * FROM t LIMIT 20`、`ReadOnlySqlValidator:18` 用 `LIMIT 0` 包一层——三处都是 MySQL 方言。驱动本身离线可用（本机 `.m2` 有 `mssql-jdbc-7.4.1.jre8`），但方言要单独一块改动。
3. **没有数据入站的 HTTP 口**：HTTP 侧只有出站 `HTTP_CALL`；入站只有 `POST /api/external/jobs/{id}/trigger`（带 `X-API-Key`，请求体可作链首输入，`ExternalTriggerController:25-31`、`trigger-flow.md:60-65`）。设备/车间系统想直接 POST 数据进来，走的就是这条，或走 MQ。
4. **交付语义是至少一次**：推送可能重复，靠目标端业务键或南向幂等键去重（`docs/features/reliability/README.md` 的「交付语义（至少一次）」）。
5. **未闭环缺陷（会直接影响 A4/D3）**：MQ 入口链的映射步重投会**静默出空**（`docs/flows/reliability-flow.md:178`，状态「待评估」）。现场表现就是「重投看起来成功、下游写库报缺列」——清场前那批配置里 `south-debug` 的 `Field 'order_no' doesn't have a default value` 就是这个现场。
6. **删任务不删动作行**：`JobService.delete` 只删任务与样例（`JobService.java:55-60`），`job_action` 会留下未删除的残留行——交付清理与配置迁移时要记这一条。

## F. 模拟真实对接的三层做法

| 层 | 做法 | 适用 |
|---|---|---|
| 1 纯本机替身 | 现有 MySQL + RabbitMQ + `tools/mock-9099.cjs`（客户 HTTP 替身）+ 内置 `/mock/mes/*`（MES 替身） | A 组绝大多数、B6、B9、D1~D4、D6~D8 |
| 2 协议替身 | 另起小进程模拟：MQTT broker + 物模型校验、OPC UA server、Modbus 从站、SOAP stub、SFTP | B1~B5、B7、B8、C1~C3、C6 |
| 3 真机/真云 | 客户预发环境，或自己的云 IoT 平台实例（华为云 IoTDA/ROMA、阿里云、根云等） | 上面两层验完之后，做一次真联调取证 |

## G. 需要你确认的信息（决定案例怎么落到具体字段）

1. 客户所在细分行业与产品形态（现有样例数据是模具：`前保险杠模具`、`MAT-718H`/`MAT-SKD61`）。
2. 客户侧 MES 是自研还是品牌产品（西门子 Opcenter / 达索 Apriso / 鼎捷 / 用友 / 金蝶 / 自研）。
3. 工业互联网这一侧是**已有平台要接**（哪个：华为云、阿里云、根云、卡奥斯…），还是**只做设备数据上云**。
4. 客户现场网络形态：能否主动出站 HTTP（决定北向推送是否可行）、是否有 MQ 中间件、是否有专线/VPN。
